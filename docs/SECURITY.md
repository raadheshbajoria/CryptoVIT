# Security measurements

Generated by `scripts/security_report.py` on 100 DermaMNIST test images (28x28 RGB), averaged. These are statistical checks, **not a security proof**; neither scheme replaces a standard cipher such as AES, and the key in the code is a public research key.

| Measure | per-pixel (v1) | block (2x2) |
|---|---|---|
| Entropy of the encrypted image (bits) | 7.74 | 6.49 |
| Entropy of ideal noise of this size (bits) | 7.77 | 7.77 |
| Adjacent-pixel correlation, plaintext | 0.95 | 0.95 |
| Adjacent-pixel correlation, encrypted (0 is ideal) | 0.14 | 0.50 |
| Key sensitivity NPCR (%) - key differs by one bit | 99.6 | 99.5 |
| Key sensitivity UACI (%) - ideal about 33.5 | 33.6 | 26.3 |
| Plaintext sensitivity NPCR (%) - one pixel changed, ideal about 99.6 | 20.52 | 0.04 |
| Plaintext sensitivity UACI (%) - ideal about 33.5 | 0.08 | 0.00 |
| Histogram distance plaintext vs encrypted (0 = identical) | 0.55 | 0.49 |
| Histogram distance to the plaintext-or-inverted mixture (0 = same palette up to inversion) | 0.42 | 0.15 |

## How to read this

* A scheme with good diffusion changes about 99.6% of the output when one input pixel changes. Both schemes here change far less, so both have weak diffusion; the block scheme changes exactly one output pixel (no diffusion at all).
* High key sensitivity only says the scrambling depends strongly on the key.
* The block scheme inverts about half of the blocks (v -> 255 - v), so its histogram is not the plaintext histogram but a mix of it and its mirror image: the first histogram row is large for both schemes, and only the second row (distance to that mixture) shows that the block scheme keeps the original palette up to inversion while the per-pixel scheme flattens it to noise.
* Adjacent-pixel correlation is high for natural images; a good cipher drives it to about 0.
* The block scheme is a deliberate trade: it gives up security to stay learnable by a ViT.
